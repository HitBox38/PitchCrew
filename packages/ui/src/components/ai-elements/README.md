# AI Elements in Pitchcrew

Pitchcrew follows the current [shadcn AI Elements patterns](https://ui.shadcn.com/docs/ai-elements), migrated from its earlier Vercel AI Elements copies on 2026-10-15. Local runtime adapters and the board API own execution; these patterns do not introduce a provider loop.

The Base UI `base-vega` registry sources were extracted into `packages/design-system/src/components`, split into focused files, and adapted to the app's `primitive:` styling layer. Sources: [Message Scroller](https://ui.shadcn.com/docs/components/base/message-scroller), [Message](https://ui.shadcn.com/docs/components/base/message), [Bubble](https://ui.shadcn.com/docs/components/base/bubble), [Attachment](https://ui.shadcn.com/docs/components/base/attachment), [Code Block](https://ui.shadcn.com/docs/components/base/code-block), and [Trace](https://ui.shadcn.com/docs/components/base/trace). Their MIT license is retained in [`packages/design-system/src/components/LICENSE`](../../../../design-system/src/components/LICENSE). The existing `LICENSE` retains attribution for the earlier adapted Vercel code.

- **Chat / Conversation:** Message Scroller provider, viewport, content, per-entry items and scroll button. User messages are scroll anchors. Latest pages follow streaming replies; navigating history recreates the scroller at the selected page's start with following disabled. The latest 50 entries remain mounted, and every older entry remains accessible.
- **Message:** shadcn Message and MessageContent, with muted Bubble/BubbleContent for user messages. Streamdown still renders Markdown through the shared `MarkdownContent`, with static/streaming modes, remote-image placeholders and link confirmation.
- **Prompt Input:** shared Base UI Input Group with a submit button and a small Lexical plain-text chat editor, IME-aware Enter handling, Shift+Enter newlines and stop behavior. `@`, `$` and `/` suggestions insert atomic inline references; sent chips retain server-validated identity and saved labels through `ChatReferences`. See [chat references](../../../../../docs/chat-references.md). The app owns selected files, drop/paste handling and requests. Text and files clear only after successful requests. Files render through shadcn Attachment in the composer and transcript.
- **Code Block:** shared Markdown fences use CodeBlock, header/title, exact-text copy and keyboard-scrollable content. Inline code remains inline. Outside Markdown, `components/SourceBlock` composes the same primitive for setup/service commands, action JSON, skill/instruction source reviews, profile imports and comparisons, packet text and browser evidence. It retains exact text, uses labelled copy controls and bounded wrapping, and lets document views keep the reading font. The optional syntax-highlighting hook is not installed; code renders as escaped plain text, including while streaming.
- **Turn activity:** Trace collapsibles, lines, icons, titles and descriptions present bounded public activity, outcomes and elapsed time. Private thinking text and raw tool input/output remain excluded.
- **Queue:** Trace sections present the existing queued/paused/failed follow-ups; running-only requests remain excluded. Existing delivery actions and API gates are unchanged.

Patterns that need unavailable data (context-window usage, terminal output, stack frames, test results, agent plans and source citations in replies) are not fabricated. Existing Pitchcrew question, model-picker and exact-action approval flows keep their domain behavior.
