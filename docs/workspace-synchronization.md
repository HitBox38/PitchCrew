# Workspace synchronization

The mounted workspace shell owns one two-second snapshot poller and one chat SSE subscription. `GET /api/snapshot` still returns the complete authoritative snapshot, including all saved messages. Requests carrying the last `ETag` receive an empty `304` when no snapshot input changed. Both responses and conditional fetches use `no-store`; the renderer retains only the validator alongside its existing workspace state. Local-session, Host and Origin checks still run before this route.

The validator combines SQLite's connection-local `total_changes()` and cross-connection `data_version` with the actual small, non-board inputs: onboarding, packet rules, instruction-update dismissals, profile organization, runtime health/model catalogs, connector status, starter-skill errors, streaming replies and live activity. Profile note names, inode, size, modification time and change time capture external additions, replacements, edits and removals without rereading unchanged contents. Change time also detects same-length writes that preserve modification time. The validator includes a random daemon-instance prefix so reconnecting after restart cannot reuse an earlier validator. New snapshot inputs must be reflected in `packages/orchestrator/src/crew/snapshot-revision.ts`.

A matching poll skips snapshot construction, projection/history reads, full JSON serialization, response parsing and workspace replacement. It still performs a small revision check. Changing workspaces and active streams can still produce full snapshots; this is conditional transfer, not history pagination or a delta protocol.

The response is labeled with the revision read **before** asynchronous snapshot construction. A concurrent mutation therefore forces the next refresh instead of labeling older content with a newer revision. No shared mutable snapshot cache is retained. User action reloads request a full snapshot, SSE state continues to take precedence, and stream disconnection resets the validator to force the next poll to recover authoritative chat state. A generation check prevents an earlier in-flight poll from restoring a cleared validator.

Regression coverage lives in `snapshot-polling.test.ts`, workspace-store tests and API tests. It covers skipped reads/body/state updates, every non-board invalidation, external SQLite writes, asynchronous snapshot races, disconnect races and failure recovery.
