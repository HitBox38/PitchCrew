# Workspace synchronization

The mounted shell owns one two-second snapshot poller and one chat SSE subscription. The renderer requests `GET /api/snapshot?view=workspace` and `/api/chat/stream?view=workspace`. These session-protected projections contain the latest short preview for each conversation, unread/count metadata and the same latest 100 eligible notification messages as the notification panel. They omit job descriptions and captured source HTML; opening a job loads its complete source through `GET /api/cards/:id`. Saved run configurations and activity bodies are also omitted from the workspace run list. Canonical board records, runtime prompts and agent-scoped tools retain their complete data.

The ordinary `GET /api/snapshot` and chat stream retain their full-history contracts for existing callers. A workspace response is explicitly marked `workspace: true`; consumers must fetch job source and conversation history rather than treating its previews as complete documents. Packet contents and approval artifacts remain in snapshots; the projection is not a universal size cap for document-heavy workspaces.

## Conversation history and search

`GET /api/conversations/:id/history` returns the latest 50 message/activity entries and full counts. Older and Newer requests use stable entry-ID anchors; Latest removes the anchor. A partial SQLite thread index narrows message/run reads. The page query reads position metadata first and parses bodies only for the selected entries. Timestamp ties, triggering-message/turn/answer ordering and saved activity follow the existing transcript semantics. New replies do not shift an anchored older page. Opening another conversation or leaving Chat releases the loaded page; the store does not cache complete histories.

The renderer merges current streaming replies and run activity into the latest page while keeping at most 50 mounted entries. The compact stream sends active turns and their final saved state once after activity leaves memory, retaining Node backpressure and disconnect cleanup. The renderer retains all active overlays and at most 50 recent terminal overlays; complete older activity remains accessible through history pages. Reconnection reconstructs current stream state.

`GET /api/conversations/search?q=...` searches every persisted message and attachment name, including archived conversations and entries outside the loaded page. The sidebar combines those thread IDs with its existing title/participant matching, archive controls, ordering and unread markers. Search is debounced and obsolete requests are aborted. Loading failures expose an error and retry instead of displaying an incomplete history as empty. Browser find and text selection cover the displayed history page.

## Conditional polling

Requests carrying the last `ETag` receive an empty `304` when no snapshot input changed. Full and workspace views have separate validators. Responses and conditional fetches use `no-store`; local-session, Host and Origin checks run before these routes.

The validator combines SQLite's connection-local `total_changes()` and cross-connection `data_version` with the actual small, non-board inputs: onboarding, packet rules, instruction-update dismissals, profile organization, runtime health/model catalogs, connector status, starter-skill errors, streaming replies and live activity. Profile note names, inode, size, modification time and change time capture external additions, replacements, edits and removals without rereading unchanged contents. Change time also detects same-length writes that preserve modification time. A random daemon-instance prefix prevents validator reuse after restart. New snapshot inputs must be reflected in `packages/orchestrator/src/crew/snapshot-revision.ts`.

A matching poll skips snapshot construction, projection/history reads, JSON serialization, response parsing and workspace replacement. Changed workspaces and action reloads receive the current workspace projection. The response is labeled with the revision read before asynchronous snapshot construction: an intervening mutation forces another refresh rather than labeling old content as current. Concurrent workspace requests carrying the same revision share only an in-flight projection build. Its entry is removed on success or failure; different revisions never join it, and completed snapshots are not cached.

Live chat state continues to overlay streaming replies and activity. A newer persisted message revision supersedes older stream history, so externally appended messages can recover through polling. Stream disconnection clears the validator for an authoritative fallback; a generation check prevents an earlier in-flight poll from restoring it.

Regression coverage includes snapshot polling, workspace store/stream merging, full/compact HTTP contracts, session enforcement, notification eligibility, complete history traversal, timestamp ties, anchored pages, Unicode/attachment search and terminal run handoff. Native verification checks the actual hidden renderer, history navigation/search, job source loading and existing composer/approval interactions.
