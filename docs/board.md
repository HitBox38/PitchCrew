# Board

Rules for contributors and coding agents. If a change makes anything here false, update this file in the same change.

Board's title row holds Pipeline | Closed (with counts, "N of M" while searching), Search jobs (all jobs, before sorting and paging; Escape clears), Jump to (the five stages; scrolls to and focuses the column) and Add job with Import applications under its caret. A Needs you decision deck (318px; one waiting packet, browser request, question or unconfirmed brief at a time with its existing actions, the next two below, a one-line "Nothing needs your decision" when empty, a strip above the columns below about 1124px of work width) sits beside exactly four pipeline columns: Leads, Shortlisted, In progress (drafting through awaiting approval) and Applied (submitted through offer); Closed is a separate view. Each column has its own device-saved sort (fit high/low, date added newest/oldest, recently updated, company A–Z/Z–A, title A–Z/Z–A; default fit high to low with unscored last), 20 jobs per page (40 in Closed) with accessible Previous/Next and full counts, and up to five state beads; moves reveal their destination page before focus returns. Drags show a target for each exact status, a grouped column never picks a status on drop, and Move to… keeps every status. Cards show the recorded status for applied/closed jobs and fit as an ink number or a "Not scored" dash. The Board setup checklist sits inside the deck, and phones show one stage at a time through a stage selector.

**Board.** One card per application. Allowed transitions live in core. Agents coordinate through persistent board state; launches start with user actions or stored routines and can continue through bounded board-backed agent tasks. Users can register known external submissions with a timestamp and confirmation note without generating or exporting a packet; registration performs no outward action and prevents likely duplicate company/title/URL or job-ID records. Existing pre-submission cards support a narrow user-only external fact registration that rejects active work, retains prior packets without identifying them as submitted, invalidates unused approvals and preserves history. Users can bulk import past applications from JSON or CSV (1,000 rows, 2 MB) through a user-only preview and digest-checked apply: never-submitted rows become packetless leads (or shortlisted/withdrawn), submitted rows reuse external registration and then walk valid transitions with history effective times, taking the shortest valid path when legacy history does not fit. Import never changes existing cards, skips likely duplicates, keeps legacy notes and unfitted history in the tracking note, maps new imports’ weight and lessons to structured learning fields while retaining the original note provenance, and stays retry-safe through a per-row import key in the card event message, so it needs no new event version. `scripts/convert-legacy-tracker.ts` converts a legacy SQLite tracker. Agents have no import tool. User-only drag status changes can record any status without an export; workflow moves and email reconciliation into submitted still require successful current-packet export. Card details expose user-managed job identifiers, Gmail thread links, tracking evidence, learning signals and, for discovered leads, their job source.

**Approval.** Exact packet snapshot and SHA-256 digest bound to a card, confirmed application context revision, independent packet review and export action. It is single-use; export calls enter the shared MCP gate. Agents have no approval tool. Successfully exported current packets allow workflow submission recording. Manual board status changes record user bookkeeping independently and do not authorize export or browser submission.
