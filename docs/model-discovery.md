# Model discovery

Crew settings load models when the form opens and when its runtime changes. Every runtime uses the same searchable picker and CLI default option. The model picker and Save settings button are disabled while the selected runtime is unavailable; Refresh models can recheck availability. Runtime results replace the curated suggestions, rather than merging unverified suggestions into a live catalog. A successful empty result remains empty and asks the user to check the CLI's native authentication.

| Runtime                         | Discovery                                                                                                                                               |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex                           | Private `codex app-server --listen stdio://` connection; initialize, then paginate `model/list` with hidden entries excluded.                           |
| Claude Code                     | Private stream-JSON SDK connection; read `models` from the `initialize` control response and exit without sending a user message.                       |
| OpenCode                        | `opencode models --pure --verbose`.                                                                                                                     |
| GitHub Copilot CLI              | Private `copilot --headless --stdio --no-auto-update` connection; connect (or legacy ping), then `models.list`. Models disabled by policy are excluded. |
| Cursor Agent                    | `cursor-agent --list-models`.                                                                                                                           |
| Kiro CLI                        | `kiro-cli chat --list-models --format json`.                                                                                                            |
| Grok Build                      | `grok --no-auto-update models`.                                                                                                                         |
| Pi                              | `pi --list-models` with extensions, skills, context files and sessions disabled.                                                                        |
| oh-my-pi                        | `omp models --json --no-extensions` (chat models).                                                                                                      |
| Gemini CLI, Goose, Hermes Agent | Curated suggestions: no standalone model-list operation is integrated.                                                                                  |
| Demo                            | No model.                                                                                                                                               |

Discovery is separate from `detect()`, which still only checks CLI versions. Runtime metadata requests never send user prompts, start inference turns or sign-in flows, or persist conversations. They use the CLI's native authentication and configuration; Pitchcrew never reads provider credential files or handles tokens. Commands run outside the project directory, disable ambient extensions where supported, and filter connector OAuth configuration from the environment. Claude Code uses safe/restricted mode, empty tools and MCP configuration, no session persistence, empty setting sources and disabled hooks; CLI-managed policy remains in force. Its native `default` selector clears a model override, while the shared CLI default option omits `--model` and lets the CLI resolve configuration normally. Only normalized model selectors, labels and supported reasoning levels/defaults enter snapshots; other metadata and diagnostics are discarded. Runtime-reported models are not a guarantee of account entitlement or successful execution, and the catalog can include built-in or cached CLI models.

The daemon caches each result in memory for five minutes and deduplicates concurrent requests. **Refresh models** rechecks the runtime version and bypasses the cache. Missing, unsupported, failed or malformed runtimes receive a labeled curated fallback. Discovery has a ten-second timeout, a two-megabyte output bound, catalog size and selector limits, and is cancelled when the daemon closes. No model catalog is written to board events or role configuration. Selected `provider/model` values persist unchanged, and previously saved values remain visible even when absent from the current catalog.

The session-protected loopback endpoint is `POST /api/runtimes/:id/models` with `{ "refresh": false }` (or `true` for a forced refresh). It returns `models`, `modelSource` (`runtime`, `fallback`, or `none`) and `modelDetail`.

## Reasoning

Missing built-in production agents choose recommendations from installed runtimes and their catalogs before seeding. **Use recommended setup** in a built-in agent's settings repeats machine detection and refreshes every installed runtime's catalog. It fills the editor only; saving remains a user settings action. Recommendations use advertised effort levels only and preserve provider-qualified model selectors. See [default crew recommendations](roles.md#default-crew).

Agent creation and settings offer **Default reasoning** when an explicitly selected model advertises adjustable reasoning. **CLI default** leaves the native reasoning option unset. Existing roles have no reasoning override. Changing model or runtime in the editor resets reasoning to CLI default; older API callers that omit reasoning preserve it for the same model/runtime and clear it when switching.

Codex retains `supportedReasoningEfforts` and `defaultReasoningEffort` from `model/list`; Copilot retains supported/default efforts only when its capability says reasoning effort is configurable. OpenCode's verbose model output supplies variant names; Pi's table marks thinking-capable models; OMP supplies the exact `thinking` effort list. Claude Code retains `supportedEffortLevels` when `supportsEffort` is true in its SDK model catalog; its curated Sonnet, Opus and Fable aliases advertise effort levels only when native discovery falls back to suggestions. Other runtimes, unknown model IDs, and CLI-default model selection have no separate reasoning picker. Cursor keeps reasoning presets in its model IDs. Metadata is bounded and reduced to recognized level names; credentials, costs and arbitrary provider metadata remain discarded.

Adapters pass the effective value through Codex's `model_reasoning_effort` config override, Claude Code's `--effort`, Copilot's `--reasoning-effort`, OpenCode's `--variant`, or Pi/OMP's `--thinking`. No override adds no argument. A reasoning setting grants no tools or capabilities.

Chat provides **Agent default**, **CLI default**, and the supported levels. Choices apply to subsequent user messages in that mounted conversation and are scoped to thread, recipient, runtime, model and saved default. They do not update the role; workflows, routines and agent follow-ups use its saved default. Each chat run snapshots its effective reasoning. Unsupported values fail before creating a message or run. Only user-session role settings/creation and chat requests accept reasoning; agents cannot change it through proposals or gateway tools.
