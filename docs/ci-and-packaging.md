# CI and packaging

Rules for contributors and coding agents. If a change makes anything here false, update this file in the same change.

GitHub Actions CI runs on every pull request, pushes to main, merge queues and manual dispatches. Every run checks lint, formatting, types and production builds on Ubuntu, runs the full Vitest suite with Chromium on Node 22 and 24 across two shards per Node version with two workers per shard, independently verifies the actual Bun daemon/MCP/bounded helpers, and runs the actual Electron smoke test on macOS and Windows. Full installer builds and packaged-app checks on Windows x64, macOS Apple Silicon/Intel and Linux x64 run for pull requests targeting main, main-targeted merge groups, pushes to main and manual dispatches on any branch. Ordinary feature pull requests and merge groups targeting dev skip the installer matrix; packaging-specific failures may first surface on the release pull request, and a manual CI run can verify a feature's installers earlier. The quality job supplies one installer-policy output for both the matrix condition and aggregate CI gate. The gate requires quality, tests, Bun runtime integration and Electron smoke success, plus successful installers when required or an intentional installer skip otherwise; missing policy values and unexpected skips, failures or cancellations fail the gate. CI reads the Bun pin from `.bun-version`, installs from frozen `bun.lock`, caches package downloads by operating system/architecture and lockfile, and retains read-only repository permissions without provider credentials. Package caching never skips install or Chromium/system-dependency setup. Installer artifact uploads disable outer compression and retry once after 30 seconds when the upload action fails, replacing any incomplete artifact with the same name; a failed retry still fails the job. The GitHub main branch ruleset requires the aggregate CI check from GitHub Actions and an up-to-date branch, with no bypass actors. Main push runs have distinct concurrency groups so every push can produce a release; other superseded runs are cancelled. Test reports, desktop evidence, installers, macOS ZIP update payloads, architecture-specific updater manifests and blockmaps are retained for seven days. The separate Release workflow downloads artifacts concurrently from the exact successful CI run and publishes those verified installer/update artifacts and SHA-256 checksums after successful main push CI under build-<full commit SHA> tags; only it has contents write permission and it never executes repository code. Reruns resume drafts or skip published releases. Windows and macOS installers are unsigned, and macOS builds are not notarized.

Standalone desktop packaging uses electron-builder with an isolated app directory and an unpacked runtime resource tree containing the source-layout daemon, production-only hoisted dependencies with workspace links materialized as directories, the pinned Bun executable, the build machine's Node 24 helper and Chromium. Bun runs the daemon and MCP, while genuine Node helpers retain bounded V8 workers for document/database parsing and verification. Native SQLite remains outside Electron, so Electron native rebuilding is disabled. The packaged main process forks the bundled launcher, which retains daemon/service reuse and ownership rules; closing the app stops only its own daemon, and launcher IPC disconnect handles Electron crashes. Windows NSIS setup and uninstall use the scoped process check in `packages/desktop/installer/`: only the app executable and exact bundled Bun/Node/Chromium helpers under the selected or previous installation directories are closed; legacy Node helper paths stay recognized for upgrades, with a graceful window-close interval before forced cleanup. Existing installation directories expand Windows 8.3 aliases before comparison with executable paths. Downloads, the running installer/uninstaller and sibling paths are excluded; PowerShell profiles never load. Windows installer CI also runs the compiled NSIS macro against isolated fixtures, including short paths, without changing installed apps, registry keys or shortcuts. User data remains outside installation resources in the existing data directory. Source desktop launches keep their existing launcher. Build installers on each target platform/architecture with pinned Bun and Node 24; provider CLIs/authentication remain separate.
