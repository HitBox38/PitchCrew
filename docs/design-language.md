# Design language

Rules for contributors and coding agents. If a change makes anything here false, update this file in the same change.

React and shadcn/ui (Base UI primitives), Tailwind, Vite 8, shared browser/Electron renderer. Shared buttons, inputs, textareas, checkboxes and switches carry the app's clay, glazed and recessed materials without requiring a form wrapper. Switches use recessed tracks, glazed checked tracks and raised thumbs; keyboard focus remains visible above material shadows. Multiline fields respect their row count, while the chat composer grows with its content. Form selects share the app select wrapper and bounded menu height; date/time fields compose a shadcn Calendar (React DayPicker), Popover and Intent UI's registry TimeField (React Aria editable segments) while retaining local wall-clock values for the chosen timezone. Use shared controls instead of native selects, date/time dialogs or checkboxes. Compose with `render`, not `asChild`; `Button` defaults to `type="button"`, so submit buttons need `type="submit"`; menu labels sit inside `DropdownMenuGroup`.

The app has one design: clay. Feature styles target their components directly; there is no interface switch or design preference. Bead stage tracks show where a job stands in job chats and job details (with who the job waits on, in place of the matching status pill; the current Applied step names the recorded Screening/Interviewing/Offer outcome, and the next-step line and job details' footer action share one brief/form/fit/review/export gate order in `packages/ui/src/lib/job-step.ts`, so a scored lead offers Shortlist first with Evaluate again beside it), and step beads mark job details' Application and History. Chat shows participant pebbles with working or waiting beads, Job and read-only Packet side-panel buttons for job chats, a next-move line beside the stage track, one recessed thread joining each turn's inline steps and runtime label to its reply, a composer runtime chip and round send, outcome beads on turns, steps, queued messages, questions, crew follow-ups and sidebar conversations, a stage bead on the unlocked composer's job chip in place of per-message job links; locked job chips yield to the matching job header, grooved day dividers, clay starters, recessed Crew work and read-only trays, and raised pebbles for chosen participants. The compact browser panel has two rows on one paper: the agent, one bead-coloured state chip (Idle and You're browsing unfilled; You have control, Working, Needs your OK and Paused filled, with You have control ochre while a run waits on the user; it opens task details with the permission mode, task and site access), a hairline, the page's tabs inline (a lone tab is its title as plain text; New tab sits outside the scrolling, fading tab list; dragging a tab, Control+Shift+Page Up/Down or the tab menu’s Move tab left/right reorders tabs as a user-only command, and a recovered crashed tab keeps its place) and the panel actions, then navigation, a host-and-path address (lock only for a committed HTTPS page, Open in system browser on hover), Find as a floating pill ("3 of 12", "No matches"), history (title then host and path; a quiet clear row that asks first) and Page settings (a quiet menu of tool, zoom, option rows and a three-way appearance segment) with only a running recording's stop control on the toolbar; the page runs flush under the toolbar's hairline in the split and expanded views. The approval tray reserves 56px for the whole open session (autonomous preparation lists its steps in a taller tray), so runs starting or ending never resize the page: a waiting request reads as two lines on an ochre tint — what will happen, written by Pitchcrew with the exact value ("Open example.com", "Click “Learn more”", "Type “jane@…” into “Email”", "Upload resume.pdf to “Resume”", or "Click an element on host" without a name) and the agent's reason — while a still dashed ochre ring marks the target on the live page (a "Target below/above" pill at the page edge when it is mostly out of view; titles shorten the value, never the target; Control/Command+Enter approves from a non-field control in the panel, the request's two lines open Details, which can decide too, and while a request waits the page keeps its inspected size, framed and captioned when shown in a larger area) (its box comes from the referenced element at request time, stays in daemon memory outside the approval event and digest, and is served through a session-protected route) — with Site access, Details, a verb-specific approval first ("Approve click", "Approve typing", "Approve submission") and Reject, and never resizes the page; narrow headers keep a fixed shape so state changes cannot reflow a page under review. The reserved tray's quiet line adds what the chip doesn't (the agent's latest step while it works, or what holding the page means) in up to two lines and ends with the one control action that means something (Take control while an agent works, Return to agent after an explicit takeover, Recover control when it lapsed), so the header never changes width; × shows in the split view and narrow sheet (below 900px the panel is a sheet with its own message box; between 900 and 1152px an open browser folds the sidebar to its rail so the panel keeps at least 32rem), the resting tray is a recessed line that rises only for a decision, the chip is a fixed-width pill in every run state (its slot reserves the widest, "You have control", plus its hairline in panels wider than 30rem, so the tabs shift only when a run starts or ends, and hugs its label at rest), the selected tab scrolls into view and narrow panels drop the agent's name for its avatar; while no agent run uses the browser its controls work directly and the first action takes control implicitly, handed back automatically when a run starts (Browser options offers "Keep control until I return it" for the idle case), a press on a page the agent is using flashes the chip ochre, relayed agent pointer moves draw a plum cursor named for the agent that rests faintly during the run, fades once the page navigates or the run ends (timed in script, so it also settles with reduced motion), stays clipped to the page and is cleared when automation releases it, and the chat header's Browser button reads as pressed while open with an ochre dot for a waiting approval and plum while an agent works; opening, empty (with recently closed tabs) and failed or crashed pages use clay orbs with only the existing open, take-control and reload actions; blocked-request warnings, website dialogs and one-line site-grant requests use clay notes; uncertain browser submissions become a "Did the application go through?" card with the existing resolve actions plus Show the page (view only, since control stays locked until the outcome is recorded) and Ask Tracker to check Gmail, which only prefills a draft the user sends. The stopped-preparation note offers I'll fill it (take control) or Continue, ask each step (hide the note), the automatic-preparation tray counts fields filled on the current inspected form page and offers the conversation's Stop, and site grants open from a Site access popover so the reserved tray never grows. Job chats with a browser-capable agent show Packet | Browser tabs of one right panel whose page region only hides so native guests park and keep their viewport; the header shows the state chip (the permission mode is in its task details), and the expanded browser puts the agent's live activity (its latest run here once that ends, ending on its reply preview; before any run the column narrows to the message box and tray), Stop, a message box that edits and sends the conversation's shared chat draft through the composer's send path, and the approval tray beside a full-height page, where Back to chat or Escape (after any open menu, dialog or field) returns to the split chat view. Job chats lead with company, title, fit and location and show recessed job-event chips (status moves, drafts, brief confirmation, review, approval and submission) from snapshot data plus older moves loaded on demand from the session-protected, read-only, paged `GET /api/cards/:id/changes` route; turn headings label models from already-loaded runtime catalogs; the composer shows a recipient chip that follows daemon routing (the agent, or "Everyone" unless the draft @mentions participants), a "Sends after <Agent> finishes"/"Interrupts <Agent>" line and a rose clay Stop. Crew work shows role and skill proposals as clay cards with a plum "Proposed by" chip, changed instructions, capability beads or exact skill text and a Decisions-style footer; chat side panels, attachments, Memory used, answered/cancelled questions and continuation/related bars use clay sheets, trays and beads; and Crew cards show today's run timeline. None of this changes actions or approvals. The public landing page builds its own marketing-scale beads, grooves, trays and pebbles from the design-system tokens and imports no app styles or components.

Pages follow the agreed clay mocks. Crew is a 4/3/2/1-column roster of agent cards (identity pebble, runtime · model, one capability line, today's run groove with a keyboard list of runs, a status tray opening the exact run, the waiting chat or the relevant setup, a quiet Chat action and a Configure/Compare/Skills/Pause menu) with a Waiting on you section for default updates and role/skill proposals, plus Kept-instructions and Retired disclosures; agent settings is a 480px panel with a sticky section index, grouped tool switches that say why a granted tool is not active yet, a Changes/Current/New default compare view and one Save footer disabled while the agent runs; New agent is a 760px dialog with a labelled bead stepper. Profile has a title row with Insights, Sources (with a review count) and New note, notices only for saved proposals or finished source reads, a full-width editor workspace with a resizable, hideable note explorer (a "Notes N" header with new note, new folder and a Notes options menu holding Recently deleted and the notes folder path; full-width search over names and text with highlighted snippets that open the note at the match; row and right-click menus for rename, move, copy, delete and folder rename/delete), joined open-note tabs with right-click menus and middle-click close, an outline popover and Write | Split | Preview, a formatting toolbar band kept in every mode, and a pinned status bar with the path, current section (the one in view while scrolling, otherwise the caret's), caret, words, the truthful save or run-blocked state (saying when autosave is off) and an editor options menu (autosave, Markdown syntax, shortcuts). Notes are named in words from their filenames ("Work-history.md" shows as "Work history"). Explorer width and visibility, the view mode and open tabs are remembered on this device; tablet windows start with the explorer closed, and phones start on the note list. "Cited in N packets" opens real packet claims in an optional wide-screen rail or a compact popover; selecting a quote reveals its exact line in Write, while quotes missing from the current draft say so; the Sources dialog is 720px. Skills is a recessed library (Updates group on top, Starters disclosure at the bottom) beside a paper document pane where Add, Import and Edit open the shared Write | Split | Preview Markdown editor with assignment chips and Save ⌘S; its agent filter is one URL-backed select. Insights shows a recessed figures strip, career plans as clay cards (created in a 560px dialog), a sortable tag table, signed weights, outcome-segmented lessons with Show all and a closed Tidy up disclosure. Routines lists 64px schedule rows in one recessed tray with an enabled switch, says whether the background service or the open app runs them, and edits in a 480px side panel showing the computed next run. Activity groups events into day trays with a state bead and a link to the job, conversation, run or page, 50 at a time. Empty chats show one purpose line and up to three quiet starter rows above the composer (longer lists fold into "N more starters"), and chat sits directly on the shell's paper with Conversation | Crew work in its header, below the phone title bar. The file viewer is a 20px-radius clay dialog with a 44px toolbar, a recessed reading area and a file list when several files are open; job details is a 680px sheet with sans headings, an ink fit number and sections separated by hairlines. Add/Edit job is a 640px dialog (link + Fetch, company/title, location/salary, full description, tags, Already applied group, Ask Scout fallback) and Import applications a 960px dialog with Choose file / Review / Result steps.

Shared design rules: Source Sans 3 type tokens (titles 21/28, sections 16/22, body and labelled buttons/tabs/answer choices 14/20, metadata 12/18 in muted ink), a flat paper ground with clay relief only on objects, at most two depth levels, one glaze action per surface, desktop targets of at least 32px and 44px under 768px or coarse pointers. Bead law everywhere: ochre waits on the user, plum means an agent is executing, rose failed, primary completed steps, moss recorded positive outcomes and an empty socket idle work; a job's current stage at rest is a neutral ringed bead. On phones the 48px top bar holds menu, page title (chats show their conversation title or attached job, opening the conversation menu; compact Conversation/Crew work tabs sit below the phone title bar), the page's primary action through `WorkspaceHeaderPrimary` (New note on Profile) and an overflow with Search, New and the bell when a page fills the bar; the drawer has a 45% ink scrim. While a modal is open, toasts stay 16px above the real top of its pinned footer, and opening a review dismisses its "ready to review" toast. Board deck question cards keep a "Company · Role" line; cards show "Not scored" for unknown fit and a status line for in-progress work. Question cards keep the labelled free-answer field outside the scrolling question/choices area, directly above Cancel and Answer and continue; Decisions' job rail prints a shared day once when all steps share a minute, otherwise relative dates. Queue lays one queue across its section tray and two or more in equal columns; waiting-on-user states are ochre and only failed work is rose. Activity rewrites stored wording into one product sentence per event, with import keys and effective dates behind Details, and still searches stored text. The Crew compare footer offers Keep mine, Edit from new default and Use new default. Profile's phone document toolbar is one 44px row whose tab lane scrolls on its own, and Profile and Skills documents follow the app theme in dark mode with a Source Sans Write editor.

Motion for React supplies pointer-driven card tilt on Closed-view job cards, Closed-view layout changes, proposal and approval decisions, new chat message reveals and question cards that spring from behind the message composer. Question cards return behind that input on resolution and become inert during exit; existing conversations and snapshot refreshes do not replay their entrance. Base UI surfaces use shared interruptible CSS transitions; frequent navigation and the command palette stay instant. Buttons use brief CSS press feedback. The motion motif is clay that morphs: clay, glaze and sunken shadow tokens share one three-outer/three-inset layer structure so raised, pressed and recessed states interpolate rather than snap; switch thumbs squash under a press, checkbox checks draw in left to right, a TabsList containing the design system's `TabsIndicator` (chat Conversation | Crew work, Packet | Browser, Write | Preview, the Settings rail, Packet rules, runtime setup steps, job details' Job | Application | Activity, Insights lessons and the job chat's packet documents) shows one clay pebble whose leading edge reaches the next tab first, and accordion panels interpolate between zero and their natural height (`interpolate-size`; their own vertical padding collapses with them, and browsers without it snap). Copy buttons morph their icon into a check through the shared `data-slot="icon-swap"` pattern (two stacked icons, the second shown with `data-swapped`), live agent beads and Crew pebbles breathe with a slow scale swell while a run executes, and the queue meter's fill flows between levels. Mount entrances use the shared `clay-emerge` (small objects: the composer's Stop and file chips) and `clay-settle-in` (new lines: a running turn's steps, an empty chat's purpose line and staggered starters) keyframes, which reduced motion redefines as plain fades; saved history never replays them. Sending a message that dispatches immediately morphs it iMessage-style (`ChatView/send-flight.ts`): everything is read before the send writes to the page, so in the send's first frame an aria-hidden copy of the bubble forms over the composer's text and rises on the compositor to just below the last message (a cubic-bezier with a 3% overshoot and pixel transforms only, since Chrome composites neither `linear()` easing nor percentage translates). A frame later a pending copy joins the transcript as the newest entry and is pinned explicitly (the agent's turn often renders first, and the scroller pins only a last entry); the scroller's jump becomes a slide of the transcript, which the bubble rides with the same curve and length, and it hands over once the slide ends while the message's "You" line fades in. The saved message renders under the pending copy's key, so nothing remounts or re-pins; a failed send removes the copy and keeps the draft. Queued or held sends and reduced motion skip it. Keep new clay/glaze shadow values in that structure. The shared `AppMotion` provider loads Motion features and respects system reduced motion; pointer-driven effects also use its reduced-motion context. Base UI retains dialog semantics, exit lifecycles, and focus management. Reduced motion removes surface translation and scaling while retaining short fades.
