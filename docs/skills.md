# Skill delivery

A skill is reusable Markdown guidance, available to all crew agents or selected agents. Assignment grants no tools or approvals. The library holds up to 100 skills, each with up to 50,000 content characters. There is no combined character limit per agent.

## Choosing delivery

The editor, import review and proposal review show **Include in every run**. When enabled, the agent receives the full text at the start of each eligible run. Otherwise it sees the skill's name, description and ID and can read the full instructions when relevant. Give procedural skills descriptions that explain when they help; a missing description does not hide the skill.

Existing saved skills keep full inclusion. New hand-written skills default to included, new imported procedures and new procedural starters default to on demand, and the bundled prompt-injection guard defaults to included. Saved text, assignments, edits, renames and deletion are preserved. Upstream updates and source reloads retain the user's delivery choice.

An explicit `$skill` selection includes the exact selected skill's full text once for that turn, even when its normal delivery is on demand. Queued selections retain revision/digest validation and cannot silently adopt changed instructions. Explicit chat selections do not automatically carry into a later ordinary **Draft application** action. That workflow sees its assigned catalog; enable **Include in every run** when delivery must not depend on an agent's relevance decision.

## Frozen reads and isolation

`pitchcrew_read_skill` accepts a catalog `skillId` and returns full instructions plus their digest from the active run's frozen configuration. It reads no path, URL or current board version and cannot select another role. Repeated calls return the same content without truncation or a cumulative character quota. Edits, reassignment and deletion affect future runs, not the active snapshot.

Eligible isolated application runs and review children can read their own assigned snapshots, which they previously received in full. Source extraction stays tools-free with no skills. Review-deadline decisions, summary-only turns, waiting-question states and external MCP clients receive no reader. Run cancellation, role permissions, conversation membership and application-context checks remain enforced.

Runtime prompts and generated `AGENTS.md` share one delivery plan. Exact `skills/<id>/SKILL.md` files remain run artifacts; runtime behavior does not depend on native file reads or native skill discovery. Native session identity includes a delivery-format revision, preventing an unchanged configuration from reusing a pre-rollout eager transcript. Later resumed sessions may retain instructions read on earlier turns.

Tool activity reports **Reading skill instructions** and its execution outcome. Successful delivery does not establish that the model applied the instructions. The runtime's actual model context remains finite, and unusually large included instructions, Profile files or history may still fail; Pitchcrew does not silently remove explicit or standing instructions to make them fit.

## Persistence and verification

Event version 35 adds the optional `includeInEveryRun` setting; versions 1–34 remain decodable without rewriting history. An absent historical setting means included. Omitted settings on edits preserve the current effective value, while service creation paths resolve defaults explicitly. Old pending proposals without a setting remain included when approved; newly created proposals record the setting before review.

Regression coverage checks importing beyond the old combined limit, individual/library bounds, legacy replay and updates, queued-reference checks, prompt/file parity, explicit deduplication, native session invalidation, frozen reads, tool discovery and restricted/external denial. Live provider compliance is outside automated verification. Run history still saves full snapshots; large-library measurements should track launch, memory and storage costs before considering a separate immutable revision store.

A synthetic local measurement on 2026-11-03 used 100 deferred skills with 50,000 ASCII content characters each. The prompt catalog was 13,126 characters; configuration cloning and hashing took 18 ms, three run-event writes took 104 ms and the instruction artifacts took 11 ms to write. SQLite occupied approximately 20.25 MB after those three events. These are one-machine observations, not performance guarantees or model-context estimates; the repeated snapshot storage remains a cost worth addressing separately.

## Contributor rules

**Skill.** A user-managed Markdown instruction with a name, description and assignment to all agents or selected roles. Manage skills on the Skills page or open it from role settings. Skills display a Made by label: the GitHub source owner for imports, the originating role for approved custom agent suggestions, or You for user-created skills. Creator and repository names are searchable. Skill creation, updates and deletion append version 35 board events; deletion uses a tombstone so replay retains history. Each eligible chat/workflow run freezes its assigned skills and writes exact isolated `skills/<skill-id>/SKILL.md` artifacts. One shared delivery plan includes full instructions for Include in every run and explicit selections in prompts and generated context files; other assigned skills expose metadata and load through the run-scoped reader. Summary-only turns omit deferred catalogs because their reader is unavailable. Edits affect future runs only, including follow-ups; active runs retain their original copy. Import public GitHub-backed skills.sh links in the editor, review the loaded Markdown and assignment, then save; the skill editor shares Profile’s Markdown editor (toolbar, Write/Split/Preview, safe preview renderer), word/status footer and Cmd/Ctrl+S shortcut. Imported skills offer an Update button that checks the registry without writing, shows name/description/instruction and source changes (or no changes), and requires explicit approval. Reviews stage the exact fetched snapshot for ten minutes or until daemon restart, preserve agent assignments, reject concurrent edits/deletion, and never re-fetch on approval. The bounded public GitHub reader uses immutable blobs, no credentials, no CLI installer and no redirects, and copies only SKILL.md instructions. Imported skills retain source URL, path and blob SHA. Skills grant no capabilities. Agents can discuss skills in user and crew chats and persist up to three suggestions per run through `pitchcrew_propose_skill`; suggestions appear in Crew work with their reason, assignment and exact instructions. Only a user decision adds the stored proposal snapshot, atomically with its decision; approval never re-fetches the source. Bundled scripts, assets, private repositories and non-GitHub skills.sh sources are deferred.

**Starter skills.** On startup, the daemon loads missing starter skills into the board before serving the workspace. Public source reads overlap runtime detection and model discovery; skill writes wait for role seeding, and readiness still waits for both. Startup failures cancel pending source reads before closing the board. The 23-entry schema-free `@pitchcrew/core/base-skills` catalog includes ten public GitHub sources resolved from their latest HEAD and thirteen bundled offline skills (ten career and Hunter skills, hiring-panel, improve-system and prompt-injection-guard); the guard is assigned to all current and future agents by default. Bundled starter identity is retained in event version 20; edits, renames and deletion tombstones are preserved, and users can add the shipped starter again from Skills. The guard supplements enforced boundaries and grants no capabilities; tools-free source extraction still receives no assigned skills. The catalog stores source paths and default assignments, never supplied version hashes. Renamed catalog repositories use explicit canonical aliases (article-writing now uses affaan-m/ECC). Writing skills default to Writer, research/questioning to Scout, and humanizer/PDF review to Reviewer. Existing matching skills and deleted tombstones prevent automatic reinstallation; edits and renames preserve source identity. Missing or offline sources are reported on the Skills page and can be retried without restoring deletions. All remote loads resolve HEAD afresh and only immutable blobs are cached; proposals still approve their exact reviewed snapshot. Individual skills allow up to 50,000 characters and the library holds 100 skills; there is no combined per-role cap. The user-owned Include in every run setting keeps full inclusion for legacy and new hand-written skills, while new imported procedures load on demand through pitchcrew_read_skill from the frozen run snapshot; the guard remains included by default. Explicit selections include their full text once. Updates preserve delivery choices, source extraction stays tools-free and native sessions reset for the delivery-format rollout. See [docs/skills.md](skills.md). view-pdf requires separate viewer tooling. Set PITCHCREW_SEED_SKILLS=0 to skip automatic seeding, as isolated automated tests do.
