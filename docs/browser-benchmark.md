# In-app browser benchmark

T3 Code is the implementation reference for Pitchcrew's desktop browser. Pitchcrew retains its clay/paper materials and its application-specific approval, scoped-session and private-control rules.

The comparison used the installed T3 Code Nightly `0.1.4-nightly.20261027.3770` (`7c3b3b3605ef`) and the public source at [`c1876b57c9258cc9a5b1a429d76e3f169bfcd9a5`](https://github.com/pingdotgg/t3code/tree/c1876b57c9258cc9a5b1a429d76e3f169bfcd9a5). Source was inspected outside this repository; no user profiles or website credentials were read.

## Architecture

| Concern              | T3 Code reference                                                                                                      | Pitchcrew implementation                                                                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Page composition     | `ElectronBrowserHost`, `HostedBrowserWebview`, `hostedBrowserWebviewStyle` keep DOM guests stable beneath app overlays | `DesktopBrowserHost` keeps one permanent shell-owned webview per main-authorized request; sheets and menus render over its live page                             |
| Ownership            | `Manager`, `WebviewPreferences`, `BrowserSession` register isolated guests and partitions                              | One-shot bootstrap tokens, exact partition and actual guest identity, main-frame/origin checked IPC, sandbox/no Node/no app preload                              |
| Agent page           | `DesktopBrowserHost`, `CdpRelay` automate the actual guest                                                             | Authenticated group-only synthetic CDP; agent inspection follows the desktop's selected tab; a disconnected desktop never silently becomes another headless page |
| Native input         | `GuestInput` handles unfocused guest keyboard/text and guest reload                                                    | Adapted input routing with the upstream MIT notice retained in `browser/input.ts`; cross-site focus checks preserve isolation                                    |
| Capture lifetime     | Actual native copies serialize, even after a caller timeout                                                            | Per-guest capture queue retains the underlying copy, bounds queue waits and rejects stale page results; credential masks remain part of agent captures           |
| Automation lifetime  | Owner/session focus and render holds release independently                                                             | Pending-command and stream owners release on detach, disconnect, navigation, crash and destruction; one viewer cannot stop another viewer's stream               |
| Link/window behavior | Ordinary links open tabs; OAuth script windows retain opener                                                           | Foreground/background DOM tabs preserve selection semantics; sandboxed owned windows preserve blank-write, POST and script opener flows                          |
| Idle macOS guests    | Visible offscreen instead of visibility-hidden                                                                         | Same parked presentation to avoid Chromium permanently blanking a guest                                                                                          |
| Browser state        | Main pushes navigation/title/loading and media state                                                                   | Narrow preload state subscription plus authoritative daemon dialog/control polling                                                                               |

Primary source directories: [desktop browser](https://github.com/pingdotgg/t3code/tree/c1876b57c9258cc9a5b1a429d76e3f169bfcd9a5/apps/desktop/src/preview), [renderer browser host](https://github.com/pingdotgg/t3code/tree/c1876b57c9258cc9a5b1a429d76e3f169bfcd9a5/apps/web/src/browser), [browser chrome](https://github.com/pingdotgg/t3code/tree/c1876b57c9258cc9a5b1a429d76e3f169bfcd9a5/apps/web/src/components/preview).

## Functional acceptance

An assertion that a button exists is insufficient. Browser functionality is checked through the native guest, daemon driver, approval manager and observable page/file/network result. UI tests separately verify that human controls dispatch the right operations and preserve their draft/context.

| Use case                                                              | Functional evidence                                                                                                                                        |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Human navigation, redirect, back/forward, reload/hard reload and stop | Fictional HTTPS responses through Electron; committed URL, history, document generation and canceled loading                                               |
| Human typing, selection, page Find and zoom                           | Trusted Electron input, selected text, actual native find matches and page zoom state                                                                      |
| Agent click/fill/select/press/hover/scroll/drag                       | Actual page values, trusted key handler, scroll position and drop handler through the production approval/action path                                      |
| Iframe controls                                                       | A second fictional HTTPS origin; inspected controls plus real frame field/action outcomes                                                                  |
| Snapshot references, conditions and diagnostics                       | Native snapshots resolve current element references, reject replaced elements, wait for changes/timeouts and sanitize diagnostics                          |
| Packet upload and final submission                                    | Reviewed/exported PDF and DOCX bytes reach a real native file input; one fictional POST receipt; uncertain-submission retry gate                           |
| Tabs, linked background tabs and popup sign-in                        | Actual owned page count, active-tab identity, opener message exchange and independent guest state                                                          |
| Private takeover, expiry and concurrent sessions                      | Agent inspection/action blocked in the affected scope; trusted manual edits survive; a separate scope continues; expired control remains private           |
| Profiles and cookies                                                  | Fictional website session cookies survive another scoped browser while another role remains isolated; selected profile applies only to new sessions        |
| Human downloads                                                       | Production download permission runs; the test automates only the native destination chooser and checks downloaded bytes in its temporary directory         |
| Device viewport                                                       | Actual `innerWidth`/`innerHeight` change to the chosen logical dimensions while compositor presentation fits available space                               |
| Screenshot, annotation and recording                                  | Real PNG pixels, canvas drawing/export/attachment, decodable WebM frames and user-only save bridge; capture ownership rechecked after awaits               |
| Separate browser window                                               | Actual hidden mirror receives live frames and forwards human input to the same original guest; source/window cleanup stays owned                           |
| App context menu, popover, dialog and sheet                           | Native compositor pixels prove overlay and live webpage update together, retaining the exact same WebContents                                              |
| Crash, failure and cleanup                                            | Real native renderer failure and a fresh same-profile guest generation and isolated host shutdown; zero owned windows/WebContents with normal process exit |

The native fixture uses intercepted fictional public HTTPS origins, temporary files and no provider calls or external submissions. It stays hidden and nonfocusable. Actual JavaScript dialogs on a DOM guest activate Electron's embedder, so the no-OS-window fixture cannot invoke them: real headless dialog decisions, native protocol handling, UI decisions and approval/submission continuation gates are separate checks. Native OS file-selection/save dialogs are tested at their chooser seam without displaying them. These boundaries are explicit, not counted as real native dialog interaction coverage.

T3's coding-specific integrations (local development-server discovery, source-code component picking and repository artifact references) correspond to Pitchcrew's agent/job/browser evidence workflows. Pitchcrew does not expose arbitrary evaluation or whole-desktop capture to agents. Browser-source keychain imports are separate from the existing reviewed cookie-export import; provider runtime credentials remain outside browser access.

Native regression work also identified two Electron-specific input distinctions: OOPIF input requires a paint-active guest hit-test region even during read-only viewing, and an emulated/stale main-frame focus record does not establish real native keyboard focus. The read-only app shield and shared guest-input routing enforce those independently. Explicit tab close waits for the actual native capture copy and destruction before selecting a survivor or creating the replacement blank tab. Session shutdown stops frame consumers and drains owned copies before forgetting guests.

Crash Retry uses a fresh main-authorized guest generation in the same scoped session/profile. The old physical target and approval evidence remain terminal; a logical tab key carries device preferences across the replacement. A new tab is not published until its blank URL/title settle, and bootstrap navigation is removed from its history. Manual history is namespaced by workspace, role and named profile.

## Verification boundary

The migration passed the full repository check on pinned Bun 1.4.4 and Node 24: 2,414 tests, lint, typechecking and production builds. Separate functional UI and hidden native browser workflows exercise the cases above, including normal native cleanup and process exit.

The [full desktop E2E suite](browser-e2e.md) additionally drives the actual built React UI, real Bun daemon, sandboxed Electron entry/preload/guests and scoped MCP stdio server together. Its twelve journeys cover navigation/input, real overlays with live compositor pixels, expansion, route persistence, tabs/history, screenshot-to-draft, exact approval/rejection, crash recovery and owned cleanup. It does not replace the broader native/API matrix with mocked UI assertions.

The general production desktop smoke also reproduced the previously documented intermittent native shutdown stall: Electron emitted `quit` within 3 ms, but its process did not exit within the separate 10-second deadline. The minimal Electron control, with no Pitchcrew imports, exited normally without a window and reproduced the stall with a hidden blank window. Forced cleanup remains a failed check; no exit bypass or relaxed deadline was added. See [desktop shutdown performance](desktop-shutdown-performance.md) for the independent reproduction and limits.
