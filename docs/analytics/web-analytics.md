# Public website analytics

The public landing page at `pitch-crew.tomer-norman.dev` emits native `$pageview` events and SDK `$pageleave` events, alongside the existing `landing_page_viewed` and `landing_download_clicked` events. BFCache restores emit a new native pageview. Existing dashboards can retain their custom events; new website traffic charts must use only `$pageview` to avoid double counting. A download click is interest in a download, never proof of download completion or installation.

The landing footer's website analytics preference is the master control. Production configuration, an empty/invalid token, Do Not Track, unavailable preference storage and opted-out storage all prevent capture. The permission is rechecked after dynamic SDK loading and immediately before every outgoing event. Pending imports and measured vitals are discarded after opt-out; there is no deferred metric queue. SDK failures cannot block downloads.

While enabled, PostHog stores a random anonymous website device ID and session state in local browser storage. This preserves returning-browser and session counts across page loads. Opt-out disables and clears SDK persistence. This is separate from app identity, with no person profiles, identification, fingerprinting, account linkage or cross-app IDs. Counts represent browsers/devices, not verified people. New instrumentation does not reinterpret or backfill historical memory-only visitor counts.

Every event passes an allowlist. The public host and path are fixed literals, `pitch-crew.tomer-norman.dev` and `/`; raw URLs, queries, fragments, referrers, campaign attribution, browser strings, geography and private content remain excluded. SDK-generated session, window and pageview IDs are retained for native session measurements. Only bounded numeric previous-page duration is allowed for pageleave. SDK referrer/campaign saving and debug logging are explicitly disabled.

Next's documented `useReportWebVitals` reports LCP, CLS, INP and FCP through a stable callback. Only name and finite bounded numeric value are read from its callback; entries, DOM elements, attribution, navigation IDs and URLs never enter analytics. Each accepted value is emitted as `$web_vitals_<name>_value` on a native `$web_vitals` event. Millisecond metrics are bounded to 15 minutes; CLS is unitless. Metrics observed before capture is ready or while disabled are dropped, so dashboards describe observed consented samples rather than every visit. Browsers without a supported metric contribute no sample, and INP normally needs an interaction.

## Native configuration and dashboard publication

`posthog/web-analytics/resources.json` prepares a separate **Pitchcrew Website** dashboard, compatible saved insights and the native download conversion goal. Publish these after integrated checks, then select `renderer = landing` in [Web Analytics](https://eu.posthog.com/project/295060/web) and add `landing_download_clicked` as the conversion goal. The descriptor is a publication plan, not evidence of live creation. Filter every insight to the landing renderer so daemon UI events cannot enter website measurements.

Native attribution, geolocation, outbound-URL and URL-specific path/vital views are intentionally unavailable because their properties are removed. Use the saved insights for fixed-path numeric vitals and traffic. Native bounce should be treated as an approximation: the SDK's definition also relies on autocapture, while this implementation excludes arbitrary interaction autocapture. Pageleave is best effort on unload, so browser closure, blocking extensions and interrupted delivery can undercount duration samples. The dashboard avoids a headline bounce-rate chart and distinguishes measured pageleave duration from time-on-task.

No replay, heatmap, frustration capture or performance-autocapture setting is enabled by this feature. Separate feature work supplies those controls. No production test events were sent and no live dashboard was changed during implementation.
