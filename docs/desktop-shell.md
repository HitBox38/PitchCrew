# Desktop shell

Rules for contributors and coding agents. If a change makes anything here false, update this file in the same change.

Electron shares the paper-themed app bar with native macOS traffic lights and Windows/Linux window-control overlays. Blank chrome stays draggable while interactive controls use no-drag regions and reserved native safe areas. Shared sheets and their backdrops fit below the app bar, including the mobile sidebar; macOS fullscreen keeps workspace controls available in that bar without reserving traffic-light space. Its sandboxed CommonJS preload synchronizes the renderer theme through a main-frame, origin-checked IPC channel with a narrow, user-only desktop update bridge and a one-shot, numeric-only startup timing bridge and a read-only blocked-link feedback subscription; a narrow browser bridge registers main-authorized DOM guests, publishes their presentation, focuses browser controls/pages and performs native Find, with the same main-frame/origin checks; other Electron APIs remain isolated. The trusted renderer permits clipboard text writes only for its current main frame at the daemon origin. Native guests permit sanitized clipboard writes and user editing-menu paste; programmatic clipboard reads and other permissions remain denied. Copy failures show manual-copy guidance. The hidden desktop smoke test verifies the MCP configuration against the native clipboard. HTTP(S) links from the trusted app renderer open in the system browser (isolated native browser guest links remain in their browser session), including job postings, Markdown links, original source documents, setup/sign-in and release pages. Main-process validation rejects embedded credentials, invalid URLs and non-web protocols; external links from the app never navigate its trusted renderer or create app windows. Script and sign-in popups use owned, sandboxed native browser windows so their real opener relationship survives; they remain in the same scoped session and follow its private-control gates. Renderer click/confirmation guards and native feedback show an app toast for blocked links, explaining invalid addresses, embedded credentials or unsupported protocols without exposing the URL, including links Chromium rejects before native handlers; failed system-browser launches show an error. Internal routes stay in the renderer, and local document downloads retain their existing flow.
