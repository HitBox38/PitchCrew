# UI architecture

Rules for contributors and coding agents. If a change makes anything here false, update this file in the same change.

Lazy pages and panels use the shared retryable loader and clay load-recovery components. Failed file downloads offer an explicit, confirmed reload; they never silently reload and discard unsent drafts. Render failures can retry locally, failed panels can close, and technical details stay behind a disclosure. Settings uses the same reload safeguards.

TanStack Router with a typed code-based route tree and browser history for both renderers. The shared workspace shell stays mounted around lazy page outlets. Route wrappers import their view directly; avoid a second React.lazy boundary inside an already lazy route. Board lives at `/`; other views use named paths, chat threads use `/chat/<thread>`, skill assignments use `/skills?filter=<assignment>`, Activity search/type filters use `/activity?q=<query>&kind=<event-kind>`, and Insights filters use `/insights?tag=<tag>&from=<local-date-time>&to=<local-date-time>&sort=<count|positive|weight|tag>`. Profile, role, skill, routine, packet-rule and job-source editors protect unsaved changes when closing, switching notes, navigating, or leaving the page. The daemon serves the SPA entry for deep links in development and production.

Main views share a viewport-height paper workspace with a compact icon/title header and independently scrolling work area. Chat and Profile retain their dedicated workspaces with matching bounds and materials. Other pages use `WorkspacePage`; feature actions reach its persistent header through `WorkspaceHeaderActions`. Feature-specific work-area layouts override the low-specificity shared body defaults. Keep editor headings, body spacing and persistent actions consistent between embedded panels and sheets.

The window is paper, with a compact global app bar and no boxed page card. In browser and Electron workspaces, a 40px app bar (48px with a coarse pointer) holds Hide/Show sidebar (Cmd/Ctrl+B or Cmd/Ctrl+backslash), Search opening the command palette, New and the notification bell on the left, and the queue indicator, conditional update indicator and Settings on the right. The queue indicator uses a fixed-size active/capacity summary, one aggregate occupancy meter and separate ochre on-hold and rose failed counts. Its rows show the Queue page's bead through the shared `queueTone` (`lib/work-queue.ts`): only a queue whose work failed is rose and counted as failed, while interrupted and blocked queues are ochre and counted on hold. Its size and rendered elements do not grow with capacity; exact counts remain available in accessible text and the popover. The popover shows working/free/capacity totals and the same bounded occupancy meter, without one element per slot. The configured concurrency limit remains 1-50. Native interactive controls are outside draggable regions and respect macOS traffic lights and Windows/Linux window-control overlays; the app bar remains accessible in macOS fullscreen. The sidebar (`ClayInterface/components/ClaySidebar.tsx`) begins with Board/Decisions/Crew/Profile with ⌘1–4 and counts (Decisions ochre; Crew plum for instruction updates and role/skill proposals; Profile ochre for source reviews), a More menu (Queue, Skills with its update count, Routines, Insights, Activity) that shows and selects the current secondary page, then Jobs (each live job with its unpinned, unarchived conversations nested beneath it, expanded independently), Chats (Find chats searching full history, New conversation, pinned first, and collapsible Agent DMs, Crew history and Archived groups), Recent (five recently opened jobs) and Crew (one row per agent with its state; opens its chat, with Configure and Pause/Resume in its menu). Conditional Getting started (reopens the Board setup checklist) and profile-source activity scroll with the sidebar content. Desktop has no pinned footer. The queue indicator opens a Working now / Up next / On hold popover; update details and explicit download/restart/dismiss actions open from their compact indicator, with manual checks in Settings > Updates and the palette. Categories collapse independently through keyboard-accessible headings and remember their state on this device. The collapsed 56px rail keeps the places and Open jobs/Open chats shortcuts while global controls remain in the app bar; phones retain their 48px top bar with the bell and a drawer whose compact footer holds the same scalable queue summary, update indicator and Settings. Pages render an open title row (`WorkspacePage`: h1, one fact via `WorkspaceHeaderFact`, a `WorkspaceHeaderSegment`, and `WorkspaceHeaderActions` on the right). The 600px command palette groups Actions, Jobs, Conversations, Pages, Settings and Crew (including New note, Check for updates and Show introduction); `requestNewNote()` asks Profile to start a note. The bell (`NotificationBell`) opens a 380px popover grouped Needs you / Updates / Messages with per-item read, explicit Mark all read, the Sounds switch and an Activity link; `NotificationCenter`, mounted once by the shell, owns toasts (clay, at most three, bottom-right) and sounds. Shared page vocabulary lives in `styles/system.css` (`.ui-title-row`, `.ui-section`, `.ui-tray`, `.ui-card`, `.ui-chip`, `.ui-row`, `.ui-field-group`, `.ui-footer-bar`, `.ui-empty`, `.ui-segment`).

Chat AI Elements follow current shadcn Base UI patterns: Message Scroller owns per-entry anchors and live following, Message/Bubble render turns, Attachment renders local files, and Trace composes public tool/thinking activity and queued follow-ups. Conversation starters are quiet rows that fill the draft without sending. App compositions of the conversation, message and prompt input stay under `components/ai-elements/`; primitives live in `packages/design-system/src/components/` and are imported through `@pitchcrew/design-system/<family>`. Older transcript pages disable following and open at the selected page start; Latest restores following. Private reasoning and raw tool input/output remain excluded. See `packages/ui/src/components/ai-elements/README.md`.

Streamdown renders chat and Profile/Skill Markdown through the shared `MarkdownContent` component and `styles/markdown.css`. Complete documents use static mode; active chat responses and commentary opt into streaming. Tailwind scans Streamdown's distributed class strings for its built-in elements and controls. Shared presentation uses shadcn Code Block for fenced code with exact-text copying and keyboard scrolling. The shared `SourceBlock` also presents CLI setup/service commands, action JSON, raw skill/instruction reviews, profile source comparisons, packet text and browser evidence with labelled copy controls and bounded, wrapping viewports; document previews retain the reading font. Shared Markdown presentation retains caller-provided remote-image placeholders, Streamdown's link confirmation and the desktop HTTP(S) URL validation.
