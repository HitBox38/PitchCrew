# Pitchcrew landing page

The standalone public site lives in `packages/landing`, using Next.js App Router, React, strict TypeScript, Tailwind CSS, Base UI/shadcn primitives, Motion and locally served fonts. It does not connect to the local daemon. Vercel deployment is deferred.

## Brief

The primary audience is tech professionals actively looking for a job who use, or will install, an AI coding CLI. The primary action is downloading Pitchcrew, with GitHub secondary. The page leads with "A crew for your job search." and proves it by showing the crew work one fictional job (Forma, Design Engineer) in front of the visitor: Scout, Writer and Reviewer run in turn, then stop on a decision that is the visitor's. Its key proof follows: "Every line traces back to you." Writer drafts from the user's own notes, Reviewer checks every claim, and nothing is exported or submitted without the user's approval; AI context still goes to the user's chosen provider. The crew and local, bring-your-own-AI operation are supporting proof. Pitchcrew is free and open source under the MIT License; users configure their own AI CLI and provider account, whose usage costs remain separate.

The page proves the claim with an interactive, clearly labelled fictional packet, explains the three gates and prompt-injection handling, follows the job across a stage track (fit, draft, submit, track), introduces the paused support crew, explains local storage and supported runtimes, explains setup in three steps beside the platform downloads and answers setup, pricing, safety and privacy questions. It makes no claims about hiring results or full offline AI operation, and uses no testimonials, counts or ratings.

Durable product context lives in `packages/landing/PRODUCT.md`; the page's direction contract lives in `packages/landing/.impeccable/surfaces/src-app-page-tsx.md`, and the documented visual system in `packages/landing/DESIGN.md` and `.impeccable/design.json`. Transient impeccable files (mocks, review captures, build state, decision-page state) are gitignored.

## Design

The page is built in the desktop app's clay design system and imports `@pitchcrew/design-system/styles.css` for its theme, materials and primitives: flat paper `#f2f1ec` (dark `#1a1b1e`), clay volume only on things you press, recessed trays for work, the glazed indigo `#3a5482` for the one primary action per surface, and the app's role tones (Scout teal `#2f6a69`, Writer plum `#76517a`, Reviewer moss `#53673d`, ochre `#82601c` for anything waiting on the user, rose for failures). Fraunces supplies display headings and Source Sans 3 everything else; both are served locally. Beads obey the app's bead law: plum means an agent is executing, ochre waits on the user, primary marks completed steps, moss a recorded positive outcome and an empty socket idle work. The landing authors its own marketing-scale beads, grooves, tracks, trays, pebbles and chips in `src/styles/clay.css` from the design-system tokens; it imports no CSS or components from `packages/ui`. Dark mode follows the system by default, with a keyboard-accessible Light / Dark / System menu in the header; a small head script applies the saved theme before paint.

The first viewport sets the one-line headline at display size over the supporting sentence and three facts (free and MIT-licensed, Mac/Windows/Linux, your own AI tool), then a recessed Crew tray: four clay agent cards (Scout, Writer, Reviewer, Tracker) with identity pebbles, their production default runtime and model, one capability line and a groove for this morning's run on the Forma job. On a motion-allowed client the roster plays a rehearsal once it scrolls into view: the runs grow in turn with plum beads, settle to primary, and a Waiting on you tray rises below holding the Forma decision with "Download for <detected OS>" and "See the packet". The server renders the finished state, so no JavaScript or reduced motion shows the same page; a Replay control restarts it. The motion uses CSS transitions driven by a `data-phase` attribute (the app's strong ease-out curve, transform and opacity only, `@starting-style` for the status text), never keyframes, so an interrupted replay retargets smoothly.

The next section is the packet up close: a Decisions-style sheet whose four ruled resume lines carry Quoted (moss) or Revised (plum) beads, beside a recessed rail with Reviewer's note, the exact profile quote and source line, and Writer's note for the revised line, with a "4 of 4 claims quoted" readout. The lines are a native radio group (click, tap, arrow keys; fine pointers preview on hover) and the note crossfades. The pinned footer's Approve packet and Request changes only change the fictional sheet (approved in primary, changes requested in plum, Undo restores waiting). Three gates follow on one clay track (Writer Quoted, Reviewer Checked, You Approved) with the posting that cannot give orders. The journey section keeps a sticky stage track (Lead to Interviewing) that fills as the visitor scrolls past four stage objects: a job card with Scout's note, a Writer chat turn with the recessed thread and the design system's Trace lines, a browser panel whose one-line approval tray answers Approve, Deny and Ask again locally, and a small board with an Insights line. The rest of the crew (Submitter, Documenter, Pipeline Coach, Career Coach) sits in a tray with "Starts paused" chips beside ruled extras. Ownership is the page's one full field of ink with the runtimes as a plain list. Setup is a labelled bead stepper beside the recessed platform chooser and clay installer cards. Questions use the design system's accordion in a tray, and the footer closes with the name at display size on deep paper.

## Development

Shared controls and theme come from the `@pitchcrew/design-system` workspace package, compiled by Next.js with explicit Tailwind source scanning in the shared CSS entry. The landing uses the shared Button, Tabs, Accordion and Trace families directly and keeps only a platform-tab wrapper for the recessed segment look. It imports no components or styles from `packages/ui`; the analytics client still shares the replay sanitizer modules with the app. The page also passes the `design-taste-frontend` (taste-skill v2) inspector at 1440, 768 and 390px with the clay materials allowed (`--allow gradient,shadow,hairline,button-fx,dashed,mono,icon-cards`, since gradients, shadows and hairlines are the app's own materials and the Crew roster is the dealt composition); interface fragments carry `data-ui` so the inspector counts them as the product's own pictures. Its working folder `.taste-skill/` is gitignored.

Use Bun 1.4.4 from the root `.bun-version`/`packageManager` pin and a supported Node engine for the Next.js build CLI, then `bun install --frozen-lockfile`. `bun run landing:dev` serves the page at `http://127.0.0.1:3000`; `bun run landing:build` creates the production build, and `bun run landing:start` serves it. Root lint, formatting and type checks cover the site; CI builds it separately from desktop packaging.

## Downloads

The server reads the latest public GitHub release without credentials, validates installer names and repository URLs, and caches the result for one hour. Network failure or missing assets leads to an explicitly labeled GitHub Releases fallback rather than a guessed installer URL. macOS has Apple Silicon and Intel options; Windows is x64; Linux has x64 AppImage and Debian packages. Architecture choices are explicit. The download section explains the separate AI runtime/account setup and current unsigned Windows/macOS installers.

## Analytics

Production counts anonymous page visits and download clicks through Pitchcrew's public PostHog project; `NEXT_PUBLIC_POSTHOG_TOKEN` and `NEXT_PUBLIC_POSTHOG_HOST` override the ingestion settings. An empty token disables analytics. Development is offline unless `NEXT_PUBLIC_POSTHOG_DEV=1`. Website analytics is on by default when configured. A quiet footer control lets visitors opt out on that device (and turn it back on), synchronized across tabs; it is hidden when analytics is unavailable. Browser Do Not Track is respected, and masked session replay stays off because the page offers no opt-in. Events use a closed vocabulary of platform and package choices; URLs, referrers, app content and error text are excluded. Autocapture, session recording, profiles, surveys, flags, performance and exceptions are disabled. Analytics failures never block downloads.

`landing_page_viewed` and `landing_download_clicked` also include the root package's `app_version`, `renderer: landing` and `analytics_schema: 2`. A visit is counted once per loaded page, including after preference toggles. Download clicks count selected installer or Releases links, not completed downloads or installations. Website identity remains independent of the installed app.

The public site is https://pitch-crew.tomer-norman.dev. On October 12, 2026, browser inspection confirmed its deployed bundle uses the app's public PitchCrew EU token and sends an ingestion request to `https://eu.i.posthog.com/e/` that returns HTTP 200. This verifies deployed configuration and accepted outbound capture; it does not establish query visibility or genuine visitor counts. Automated tests keep transport mocked and never send test downloads to the public project.

## Search and sharing

The HTML includes a descriptive search title and summary, canonical and Open Graph URLs from `NEXT_PUBLIC_SITE_URL`, social sharing images, and escaped JSON-LD describing the website, page and desktop application. Visible hero copy identifies the AI job-search workflow. Text, FAQs and download links are rendered on the server; fonts are local and screenshots use Next.js image optimization with lazy loading below the hero.

Only production with a configured canonical origin is indexable. Development, Vercel previews and builds without an origin emit `noindex` and an empty sitemap. The production sitemap includes the homepage and product screenshots; robots.txt advertises it only for an indexable production build. Previews remain crawlable so their `noindex` can be read, following [Google's indexing guidance](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

The application schema reports the real free-app offer and separate AI provider costs. It includes no invented review or rating. Software-app rich results require an actual review or rating under [Google's software-app documentation](https://developers.google.com/search/docs/appearance/structured-data/software-app), so this schema describes the product without promising a rich result. The website schema identifies the Pitchcrew site name, following [Google's site-name documentation](https://developers.google.com/search/docs/appearance/site-names).

After deployment, verify the canonical URL and sitemap on the public domain, add that domain to Google Search Console, and submit `/sitemap.xml`. Search Console ownership and submission require the eventual domain; they are not provisioned by local development.

## Later deployment

In Vercel, select `packages/landing` as the project root and the Next.js framework preset. The package's committed `vercel.json` pins `npx --yes bun@1.4.4 install --frozen-lockfile` as the Install Command so the repository's root `bun.lock` is respected, and `npx --yes bun@1.4.4 run build` as the Build Command from that package. Vercel's [Bun version guidance](https://vercel.com/kb/guide/how-to-pin-a-specific-bun-version-for-vercel-builds) uses an explicit version in the command; this project bootstraps that binary with npm's `npx` before running Bun; do not assume `.bun-version` alone pins the hosted build. Keep the Node build runtime configured for the supported Next.js engine. Supply `NEXT_PUBLIC_SITE_URL` with the final HTTPS origin for canonical metadata, robots and sitemap. Rebuild after changing that build-time variable. Without it the page intentionally stays out of search results. No domain or deployment is provisioned by the initial build.
