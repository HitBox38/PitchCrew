# Notifications

Rules for contributors and coding agents. If a change makes anything here false, update this file in the same change.

**Notifications.** Saved agent messages, pending packet/browser/role/skill approvals and unanswered default instruction updates feed the notification bell, unread history and shadcn/Base UI Toast alerts. Transient action confirmations and failures use the same paper-themed toaster and three-toast stack, with success/error/info types; they do not enter saved notification history or play crew notification sounds. Up to three toasts stack in a portaled viewport; Base UI manages hover/focus timer pauses, keyboard access, announcements and swipe dismissal. Alert actions are typed router links. Message toasts show a headline and action only; attention toasts add a normalized preview of at most 96 characters and two visible lines. Full messages remain in chat. Notification context comes from saved entities: messages, user-input questions, packet/browser approvals, role/skill proposals and instruction updates each have their own icon and action label; questions use ochre, approvals teal, proposals and instruction updates plum and messages blue accents, using theme tokens in light and dark modes. Message and attention requests have distinct sounds; sounds can be disabled in the notification panel. Browser approval toasts are suppressed when that exact pending action is already visible in the browser panel; notification history and attention sounds remain available. History never plays alerts on initial load, and repeated snapshots/stream updates do not repeat alerts. Scoped `pitchcrew_notify_user` saves an exact user-facing message with `message` or `attention` priority (three per run), without granting approval, queuing work or pausing a run. Required input uses `pitchcrew_ask_user`: it saves a structured question, ends execution, and keeps the task waiting. Inline question cards and a collapsible answer area support single/multiple choices and custom text (Enter answers and Shift+Enter adds a line, like the message composer; 1–9 pick options outside text fields, menus and dialogs; a single-choice option answers on click, with any detail already typed); the sidebar shows Waiting for you. Answers atomically save their provenance and queue only the asking agent’s continuation. Answered/cancelled questions leave attention history. Questions grant no approvals. Notification clicks open chat, Decisions or Crew, never decide requests. Notifications and sounds stay inside the browser/Electron renderer; no native OS alerts or notification IPC bridge are used.
