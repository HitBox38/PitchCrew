# Testing rules

Rules for contributors and coding agents. If a change makes anything here false, update this file in the same change.

Development UI daemons keep Vite dependency caches separate by data folder. Deliberate development-UI tests use `uiCache: 'temporary'`; backend-only fixtures use `ui: false`. Temporary cache cleanup stays inside its validated cache boundary and waits for optimization to settle.

`packages/ui/test/browser-native-job-panel.test.ts` covers a job conversation's browser panel (tools in Page settings, fixed approval reservation, the taller automatic-steps tray in every mode that acts on its own, site access in Autonomous preparation only, manual control, Packet | Browser parking and the expanded view) with the same fake native bridge as `browser-native.test.ts`, which covers the agent DM panel's page tools, profiles, approvals and guest mounting in depth.

The adapter spawn fixtures `packages/adapters/test/fixtures/runtime-cli.ts` and `acp-cli.ts` have a `tool-calls` mode (`contextFor(runtime, 'tool-calls')` from `packages/adapters/test/helpers/runtime.ts`, read as `PITCHCREW_FIXTURE_MODE`) that emits real-shaped native tool calls through each runtime's real spawn path. `cli-runtime.test.ts` uses it to check, for every runtime it covers, that a failed command echoing the run token shows only `[redacted]`; `kiro-runtime.test.ts` checks Kiro's Pitchcrew outcomes in CLI v3 and V2-engine shapes; and `acp-tool-failures.test.ts` checks that a run without steps receives only closed failures.

`packages/ui/test/fixtures/attention.ts` (`await seedAttention(service)`) records Home's shared attention cast through the board while a test daemon runs: five of five slots busy, exactly six Needs you items and three fits waiting for a slot, returning every id; `queueMoreFits(service, companies)` queues more fits behind them, and `failFit(service, company)` adds another lead whose fit stopped before it ran and paused its job queue as failed, as Corvid's did. `packages/ui/test/attention-fixture.test.ts` locks that cast, so if a queue turns blocked the fixture is wrong, not the attention model. Unit tests build snapshots with `packages/ui/src/lib/__tests__/attention-fixture.ts` (`everyKind()` holds every attention kind but the connection request, which comes only from `everyKindRemote`, so the two together hold all 17) and `busy-fixture.ts` (`busySnapshot()`: 150 jobs and 20 asks). See [Home](home.md#tests). `packages/ui/test/fixtures/pipeline-table.ts` (`await seedPipelineTable(service)`) records Pipeline's table cast: one work slot held by a running Reviewer, then nineteen leads: sixteen unscored ones for the bulk Evaluate fit outcomes its browser test checks (queued from a brief with no fit, already queued in line or failed, not sent without a brief) and three scored ones, returning every id; `giveBrief(service, cardId)` later gives two of the leads without a brief one, for the journey whose answers are lost on the way back (unconfirmed after a failed refresh, queued once the snapshot shows it); the other preflight classes are unit-tested in `PipelineTable/__tests__/bulk.test.ts`. Crew's lens tests build snapshots with `packages/ui/src/lib/__tests__/crew-lens-fixture.ts` (`cast()`, whose agents' Demo runtime is installed; `installed()` adds it to a bare `snapshot()`, which lists no runtimes, as the lens and the Queue cell hold work whose runtime is missing), and its browser test seeds `seedAttention`.
